The attempted 1.1.6 validation still showed:

```text

```

That observation disproved the assumption that the newly formed executable was necessarily the process serving the browser UI.

## 2. 1.1.5 playback defect

The recovered UI made the Songs filter and the playback context the same object:

```text
baseFilteredTracks()
  -> search + genre filter

sortedSongTracks()
  -> sortTrackList(baseFilteredTracks())

row/double-click Play
idle player Play
Play all
Shuffle all
  -> consumed sortedSongTracks()
```

A four-result search therefore formed a four-track playback universe.

### Corrected 1.1.7 playback invariant

Search/genre filtering remains a display projection. Playback from the Songs surface resolves from the full sorted `state.tracks` collection.

When shuffle is active on row playback:

```text
current = the human-selected track
future  = every other library track exactly once, shuffled
```

Intentional queue commands stay intentional:

```text
row Add to queue  -> one track
bulk Queue        -> explicit selected tracks
Select visible    -> filtered visible tracks by design
```

The repair does not reinterpret every queue command as “queue the whole library.”

## 3. Why 1.1.6 still looked like 1.1.5

Static recovery of the stripped Go executable exposed this startup path:

```text
runningVersion(existingURL)
  -> GET existingURL + "/health"
  -> parse returned version

main startup guard
  -> compare returned version length to 5
  -> compare first four bytes to "1.1."
  -> compare fifth byte to ASCII '5'
  -> if equal: open existingURL and return
```

The fifth-byte comparison was compiled directly into machine code:

```asm
cmp rbx, 0x5
jne <version-mismatch>
cmp DWORD PTR [rax], 0x2e312e31   ; "1.1."
jne <version-mismatch>
cmp BYTE PTR [rax+0x4], 0x35      ; ASCII '5'
jne <version-mismatch>
... openBrowser(existingURL) ...
return
```

The first 1.1.6 patch changed the embedded UI and contiguous `1.1.5` strings, but this immediate `0x35` was not a contiguous string and therefore survived unchanged.

So when a 1.1.5 server was already alive, 1.1.6 still classified it as “same version,” opened the old session, and exited. The visible `1.1.5` badge in the human test is consistent with that compiled branch.

## 4. 1.1.7 compiled correction

The formation tool now requires the exact qualified instruction window once and patches only its version digit:

```text
1.1.5 guard:
48 83 fb 05 75 2c 81 38 31 2e 31 2e 75 24 80 78 04 35 75 1e

1.1.7 guard:
48 83 fb 05 75 2c 81 38 31 2e 31 2e 75 24 80 78 04 37 75 1e
```

The guard remains at file offset `0x2cd120`; the changed immediate byte is at `0x2cd131`.

The executable also forms its listener from `127.0.0.1:%d` and recognizes `VEXSTREAM_PORT`; the existing implementation therefore supports a distinct server instance when the running version is not classified as the same build. This document does not upgrade that static observation into a Windows runtime PASS.
